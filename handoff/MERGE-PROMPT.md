# Copy-paste prompt for the thedoxs.com Emergent agent

Paste everything below the line into the chat of the thedoxs.com job. Point it at the GitHub repository you saved from this workspace job (replace `<GITHUB_REPO_URL>`); the same files are also in `handoff/dox-workspace-handoff.zip` inside that repo.

---

Integrate the D.O.X Workspace into this site as `thedoxs.com/workspace`, sharing this app's codebase, MongoDB database and user accounts. The workspace source is the GitHub repository `<GITHUB_REPO_URL>` (FastAPI `backend/`, React `frontend/src/`, `docs/`, `cli/`, `backend/tests/`) with a full guide in `handoff/HANDOFF.md` and the auth adapter spec in `handoff/AUTH-ROLE-MAPPING.md`. Clone it, read both guides before changing anything. Do not rewrite the workspace; port it.

Scope and rules:
1. Backend: copy `core.py schemas.py crm_routes.py document_routes.py review_routes.py message_routes.py ai_routes.py knowledge_routes.py knowledge_extract.py calendar_routes.py integration_routes.py email_service.py seed.py` into this backend and register the routers in `server.py` under the existing `/api` prefix. Resolve name clashes with this site's routes by prefixing the workspace versions with `/api/workspace/...` and updating the matching frontend calls. Install `emergentintegrations` (`pip install emergentintegrations --extra-index-url https://d33sy5i8bnduwe.cloudfront.net/simple/`), `python-docx openpyxl python-pptx pypdf`, then `pip freeze > requirements.txt`.
2. Auth: replace `core.current_user()` with an adapter over THIS site's authentication exactly as described in `AUTH-ROLE-MAPPING.md`; map site roles to `OWNER` (site admins), `TEAM_MEMBER` (staff/agents), `CLIENT` (customers/portal users); upsert the mapped user into `db.users` on each request; remove the workspace's own login/reset/change-password endpoints and the `INITIAL_OWNER_*` seeding; keep `GET /api/auth/me` returning the mapped `UserOut`. Never let the browser send a role. Keep every `Depends(require(...))`, `Repo.scope()` and `knowledge_routes.permitted_filter()` intact — they are the authorization boundary.
3. Database: reuse this site's `MONGO_URL`/`DB_NAME`. Run the workspace `seed()` with the sample-data block removed (indexes, pipeline stages, default settings only). If a `users` collection exists, store `role/active/notification_preferences` on those documents.
4. Frontend: add the workspace pages, components, `lib/` and `App.css` from the bundle; mount them under `/workspace` (nested route or `basename`), prefix all internal links and the backend-generated notification links (`/messages?thread=`, `/transactions/{id}`, `/calendar?meeting=`, `/knowledge`) with `/workspace`; replace `lib/auth.js` login/logout with redirects to this site's login/logout; reuse this site's shadcn `components/ui` if present. Keep the workspace's dark institutional theme inside the `.workspace` root element and do not let the site's global styles restyle it. Add "Workspace" to the site header for signed-in admins/staff and "My transactions" for customers.
5. Environment: add `EMERGENT_LLM_KEY`, `EMERGENT_EMAIL_KEY`, `EMAIL_FROM_NAME`, `EMAIL_REPLY_TO`, and set `APP_ORIGIN` to this site's public origin. Never put keys in the frontend.
6. Integrations: keep `/api/integrations/*` (Hermes queue/decisions/knowledge grants, Dox referral intake, service keys, prompts, CLI download). Wire this site's existing lead/contact form to call the Dox referral logic in-process so new site leads appear as workspace contacts assigned to the owner.
7. Tests: port `backend/tests/test_external_api_core.py` and `test_iteration2_features.py` to the new auth (obtain tokens via this site's login) and run them against the preview URL; then run the UI flows for OWNER, TEAM_MEMBER and CLIENT: dashboard, pipeline drag/drop, transaction detail (checklist, documents incl. client submission, people), reviews, messages (new thread needs a participant), calendar (propose/accept/decline), knowledge vault (owner upload + grant, team member sees only granted items), AI assistant streaming with sources, settings policy incl. Hermes knowledge-access rules, connections page.
8. Deliver: a short changelog of every file added/changed, the final role mapping table, the list of env vars added, and confirmation that no workspace endpoint is reachable without this site's session.

Acceptance: a site admin signs in on thedoxs.com, opens /workspace and sees the owner dashboard; a staff account sees only assigned transactions; a customer sees only linked transactions, can submit a document and propose a meeting; the AI "Ask the knowledge vault" answers only from items that user was granted.
